My master’s thesis built a healthcare SDK and specified post-quantum resilience as a design goal. The work below is that goal taken seriously, plus tools built for problems I hit in my own work and released once they had earned it, each with the measurements and the failure cases that motivated it.

cbomctl — post-quantum policy conflict analysis

Reads a CycloneDX Cryptographic Bill of Materials and evaluates it against seven national post-quantum policies at once, reporting where their requirements contradict each other. Every rule cites the section or page it was read from, names who verified it, and records whether the source is a draft. The finding that came out of reading all seven: the authorities are not disagreeing about cryptography. Germany, France and the EU recommend hybrid key establishment; Australia recommends against it while granting the same premise; the NSA does not permit it on national security systems. It is a disagreement about which failure mode is likelier, not about the mathematics.

simframe — the iOS Simulator for coding agents

MCP server and CLI that gives an agent eyes, hands and memory on the iOS Simulator. A background loop keeps the newest frame warm, so a look at the screen costs about 20 ms instead of a blocking screenshot. The screen comes back as a numbered text map with tap points rather than as an image, at roughly a fifth of the tokens. A whole flow runs in one call, each step verified against what the same action did last time, and screens the agent has seen before are answered from memory. The argument behind it is in Agents Shouldn’t Blink: perception should be a continuously running process, not a function the model calls.

Where it actually stands, measured rather than claimed. Per-step wall clock is (model round trip + launch cost + ~1.7s × n) / n for n steps per model call, and at the recorded median of n = 2 that is about 11.7 s a step — roughly six times a human tester’s 1.95 s, which includes their thinking. A recorded route replayed with no model in the loop runs at 1.82–1.98 s a step, but it decides nothing, so that is a rehearsal rather than a fair comparison. The engine’s own share is ~1.7 s of the total, which is the useful finding: making perception faster is nearly worthless, and n is the only variable worth touching. step_ratio is 1 — when a run completes it takes exactly the minimum number of steps. Accuracy is the half still unmeasured, and the story of how those numbers were corrected four times in a day is here.

sidecrew — local models behind a compile→run→mutation verifier

Claude plans and reviews; 7B models running on the machine write the unit tests; a mechanical gate decides what a human ever sees — a candidate survives only if it compiles, passes against the unmodified source, kills a deliberately introduced bug in the function it claims to test, and is not tautological. Generation costs zero API tokens and touches no network, and the data contract refuses to serialise a local run that says otherwise. The experiment behind it was frozen before it ran and is published with its negative results: TypeScript reached 0.85 of Claude Haiku’s survival rate, Swift did not clear the bar, and the 14 B model was never the right trade. Written up in A verifier beats a bigger model, The exemplar was worth one import line and The gate is only as honest as what reaches it.

credoctor — prove your git credentials, don’t read the config

For anyone who works for more than one organisation from one machine. It treats everything that must agree for one directory tree — git identity, SSH key, GPG signing key, GitHub CLI account, browser profile — as a single credential domain, and verifies it by making real calls: an SSH greeting, a fetch, a GitHub API request with that token. That catches what reading config files cannot, such as an SSH key registered on the right account but never authorised for the organisation’s SSO. Read-only by design in its first release.

Agent-ready codebases — a documented method

How to make a large codebase legible to AI coding agents: one conventions file read by every tool, skills written for the flows a single file cannot explain, and a routing table so the right one is loaded before the agent starts guessing.
